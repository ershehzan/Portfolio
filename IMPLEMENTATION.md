- Confirm identity details, education, links, and contact method.
- Receive professional portrait and approve its crop.
- Audit each repository and identify actual implemented features.
- Select 4–6 strongest projects for primary presentation; retain remaining projects in an expanded archive if useful.
- Collect project screenshots, diagrams, demos, and measurable results with evidence.

## Phase 2 — Design lock
- Confirm accent color and typography.
- Create desktop and mobile wireframes.
- Finalize design tokens and component patterns in `DESIGN.md`.
- Review the hero, project index, case-study template, About, and contact sections.

## Phase 3 — Foundation
- Initialize framework and TypeScript.
- Set up styling, fonts, metadata, and reusable layout components.
- Implement responsive navigation and page shell.

## Phase 4 — Core experience
- Build hero and About sections.
- Build project index and reusable case-study pages.
- Add verified technical toolkit and problem-solving links.
- Add contact section and functional interactions.

## Phase 5 — Polish
- Add purposeful motion and reduced-motion support.
- Optimize images, fonts, and bundle size.
- Test keyboard navigation, contrast, and responsive behavior.
- Validate all links and forms.

## Phase 6 — Launch
- Configure domain and deployment.
- Add sitemap, robots.txt, and social metadata.
- Run Lighthouse and cross-browser checks.
- Review every public claim for accuracy.
